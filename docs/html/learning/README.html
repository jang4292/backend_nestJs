#1. 읽는 순서

순서 문서 무엇을 배우나 먼저 알면 좋은 것
1 서비스 개요 → 기능 명세 이 서버가 하는 일, 기능 규칙 없음
2 아키텍처·운영 안정성 가이드 NestJS 모듈 구조, 계층과 포트·어댑터, 오류 처리, 인증·인가, 품질 게이트 TypeScript, NestJS 기본
3 Music 학습 가이드 도메인(Artist·Track·Playlist), 요청 흐름, presenter, 트랜잭션 2번
4 DB·스키마 관리 가이드 DB·테이블은 누가 언제 만드나, migration 적용과 검증, 롤백, 다른 DB 보호 SQL 기본
5 환경별 DB·설정 가이드 Local / Test / Prod 설정과 명령, 권한, 자주 나는 오류(실행 절차) 4번
6 시크릿 관리 가이드 → API 보안 학습 가이드 비밀 관리와 push 전 점검 → 위협 모델, 비밀번호·세션·인가, 외부 IdP 검증, 대소문자 경로 우회 사례, 직접 점검하는 방법 2번
7 SNS 로그인 운영 가이드 → SNS 재활성화 체크리스트 provider 구조, opt-in 정책, 다시 켤 때 점검 2번
8 배포 시크릿 체크리스트 → EC2 배포 가이드 운영 배포 순서, 시크릿 회전, 롤백 5번
9 작업 내역과 배운 점 2026-11 감사와 후속 작업 전체(1~7단계): 문제, 원인, 조치, 교훈 1~8번
10 DB 개선 가이드 남은 DB 과제의 우선순위와 단계: drift, 계정 분리, 백업, 전송 구간, refresh token 4~5번
참고 용어집 aud, iss, PKCE, fail-closed, drift, expand/contract 등 —
참고 실행 오류 이력 (이력 문서) 과거 로컬 실행 오류와 해결 과정 —

#4. 학습 자료 작성 규칙

  • 개념과 이유는 learning/에, 실행 절차는 deployment/에 둡니다. 같은 주제는 서로 링크합니다.
  • 작업을 하면 기록을 남깁니다. 문제, 원인, 조치, 배운 점을 작업 내역이나 관련 가이드의 "사례" 절에 추가합니다.
  • 문서 상단에 최신화 기준을 적습니다. 이력 문서는 작성 시점에 고정합니다.
  • 새 학습 문서는 사이트 설정에도 넣습니다. docs/html/_tools/site.config.json의 섹션 순서가 사이트의 학습 순서입니다. HTML은 원할 때 npm run docs:html로 다시 만듭니다.
  • 공개 저장소이므로 실제 서버 주소, 포트, 계정, 비밀번호는 적지 않습니다. <dev-db-host>, <dev-user> 같은 자리표시자를 씁니다.
