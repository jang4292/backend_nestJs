#5. 릴리스 점검 (develop → main)

#5.1 범위

  • develop은 main보다 커밋 11개 앞서 있습니다(이번 브랜치 병합 후 +1 merge).
  • main에만 있는 변경은 없습니다. main의 ca1272a는 merge base와 트리가 같으므로 충돌하지 않습니다.
  • main은 users와 local auth만 있는 초기 앱입니다. 기능은 PostgreSQL, Nest 기본 오류 형식, Throttler 미적용 상태입니다.
  • develop은 다음을 추가합니다.
    • MariaDB 전용 전환
    • SNS 로그인 5종
    • 음악 카탈로그와 legacy API

    • migration 체계
    • 이번 감사 보완 전체

#5.3 배포 체크리스트

  1. MariaDB 전체 백업: mysqldump --single-transaction --routines. 자세한 내용은 MariaDB 운영을 참고합니다.
  2. 비밀값을 점검합니다.
    • JWT_SECRET이 32자 이상인지 확인하고, NODE_ENV=production과 CORS_ORIGIN을 설정합니다.
    • reverse proxy 뒤라면 TRUST_PROXY=1을 설정합니다.
    • Kakao를 사용하면 KAKAO_APP_ID, Apple을 사용하면 APPLE_ALLOWED_AUDIENCES를 설정합니다.
  3. 빌드하고 마이그레이션을 적용합니다(.env.production 기준, EC2 배포 가이드).
    git pull --ff-only && npm ci && npm run build
npm run env:check:prod          # 설정 검증(DB 접속 없음)
npm run db:check:prod           # 읽기 전용: 접속·권한·pending 목록
npm run migration:show:prod     # 1765000000000-AddRoleToUsers가 pending인지 확인
npm run migration:run:prod
  4. admin을 지정합니다: UPDATE users SET role = 'admin' WHERE username = '<admin-username>';
  5. npm run pm2:reload로 재기동한 뒤 curl -fsS http://127.0.0.1:${PORT:-3000}/health가 200인지 확인합니다.
  6. 스모크 테스트를 합니다.
    • 일반 사용자 토큰으로 POST /music/tracks를 보내 403이 나오는지 확인합니다.
    • admin 토큰으로 같은 요청이 201인지 확인합니다.
    • 공개 목록 GET /music/public/playlists가 200인지 확인합니다.

#5.4 롤백

  • 애플리케이션은 이전 빌드로 pm2:reload합니다.
  • AddRoleToUsers는 npm run migration:revert:prod로 되돌릴 수 있습니다(CI가 down/up을 매 PR 검증).
  • 그 이전 migration 중 ArchiveLegacyMusicSchema와 RepairLegacyMariaDbSchema는 down이 없으므로, 문제가 생기면 1번에서 만든 백업을 복원합니다.

#10.1 첫 연결 점검: DB_PASSWORD is required.와 권한 부족

증상

  1. npm run db:check는 Dev 명령이라 .env를 읽습니다. .env의 DB_PASSWORD가 비어 있었습니다.
    • .env.test.local의 값은 정상이었습니다(#, 따옴표, CRLF 문제 없음).
    • 셸에 export된 값도 없었습니다.
    • 오류에 읽은 파일 정보가 없어 원인을 찾기 어려웠습니다.
  2. db:check:test로 접속해 보니 개발 계정의 권한은 서버의 기존 DB 하나에만 있었고, DROP이 없었습니다.
    • app_db·app_db_test에는 권한이 없어 DB를 만들 수 없었습니다.
    • 그대로 migration을 실행하면 6번째(RENAME TABLE)에서 중간 실패했을 상태입니다.

결정

Dev는 서버의 기존 빈 DB를 사용합니다. Test는 app_db_test를 유지합니다.
